⚠ Four things I found in the code while drawing this — read before picking

These are not proposals. They are what the shipped code does today, and three of the variants below exist because of them.
1. The confirmed hero's first line is always 「곧」. home-hero.tsx:238 reads next.dateLabel.length <= 4 ? next.dateLabel : '곧'. But dateLabel for a real booking comes from kstParts() (api.ts:728), which always emits N월 N일 (요일) — never a ≤4-character string. So the ≤4 arm is unreachable for server rows and a booking six days out prints 「곧 / 초코가 달려요」. The correct relative label is already computed one file up (ddayLabel, from kstDayDiff on scheduled_at) and is only used in the sub-line. → variant ①.
2. 내 일정 opens on the FURTHEST-future booking. fetchMyBookings is .order('scheduled_at', ascending: false).limit(20) and schedule.tsx groups rows in iteration order, so descending = furthest future first, today's run below it, past runs below that. Home already learned this exact lesson and fixed it in its own ranking (home.tsx:181-185, the "[FIX] 동순위 타이브레이크" comment); the schedule list never got the fix. → variant ①(일정).
3. The 인계하기 CTA asks for an action that is already finished. STATUS_MAP maps picked_up → 'handoff', and picked_up is set only after both sides confirm. So home's coral 「인계하기」 fires after the handoff, while the moment that actually needs the owner (runner_enroute + arrived_at) renders as the calm confirmed state. This is written up as docs/decisions/handoff-cta-gating.md — still AWAITING SEAN, answers A and B. Variant ④ draws both answers rather than choosing one. Note the plumbing that doc said was missing has since landed: arrived_at is in MY_BOOKING_SELECT today.
4. Black Han Sans is used up to 8× on owner home. §3/§8 say once per screen. draw-button.tsx:210 puts useDisplayFont() on every button title at 28pt, so the none state renders 지금 찾기 · 미리 예약 · 코스 둘러보기 · 크루 피드에 자랑 · 안심 센터 (5) + the hero's two 43pt lines (2) + the masthead wordmark (1). home.tsx:403 already confesses the wordmark makes it 2 and says it is not hiding that; the buttons were never counted. → variant ③, and open question 4.
