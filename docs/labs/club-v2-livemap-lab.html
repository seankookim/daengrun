Three surfaces, one lab — and three things the server still owes

Sean named these in one breath and they interlock: the host's map is where 세션 종료 lives, the pair list is where his 「perhaps the list?」 verification lands, and the pass is the thing being verified. Splitting them would have hidden the loop.

🔴 What ships when

④ 집 반환Blocked. booking_pickup_address (0060, widened 0065:43-57) admits the runner at runner_enroute | picked_up | active, or confirmed inside T−24h. The club return is booking completed + return_pending (0045:55-59) — outside by construction. Ship ④ only after the custody-aware arm lands. Until then every 집 반환 runner lives in ⑤.
③ 확인Owed. session_checkin (0030:245-266) writes attendance WHERE profile_id = auth.uid() — and it is the schema's only such statement (0030:254, one hit). The host cannot mark anyone present. The print rows in ③ are real; the 확인 stamp needs a host-side RPC with a host/backup-host party gate. Ship the list first, the stamp with its server.
①② dotsOwed. createPosPublisher (geo.ts:467-488) opens one channel per booking — run2-{id} (geo.ts:375) — and the owner is the subscriber. No session topic, no host subscription, no position column anywhere. A host map without this is a live screen that is never live.

⚠ The phone — two populations, two permanent screens

Entitlement was never the question. _club_phone_visible (0049:167-192) already implements 호스트↔전원 · 보호자↔자기 개의 수락 러너 양방향 · 그 외 호스트 경유, its lifetime gate covers unresolved custody — so 현장 반환 sits inside the window — and every reveal writes club_phone_access_log. Collection was. api.ts:3167-3168 refused it once, in words: 「연락처는 묻지 않는다 … 받아두기만 하는 필드를 묻는 건 넛지가 아니라 수집이고, §12 가 전화 버튼을 거부한 것과 같은 이유다」. Sean has now ruled the other way — numbers are collected at onboarding, owner and runner.

The half that shapes the screen: profiles.phone is NULL for every account that already exists and stays NULL after collection ships — new signups fill it, the current cohort never does unless separately prompted. So ⑥ is not a waiting room. It is the permanent 현장 반환 screen for everyone who already has an account, chat is a first-class route there, and there is no 「곧 제공돼요」 anywhere on it — an apology would be a lie about the roadmap. F3 is the other real state, not the real one: a pairing whose number exists gets the call route alongside chat, with its lifetime and its access log said out loud. Two populations, two screens, neither degraded. No number string is printed in either — the digits are a user's field, not a lab fixture.

The refusal is print, the escape is the action

② is the frame that carries the house law. club_finish_session raises dogs_not_returned while any pairing is unresolved (0048:396). So the 종료 button does not sit there filled and inert: the reason is print — the two pairs, by name, with their phase — and the one coral action is the way out (session_custody_override, 0069:137 / 0070:243, return_pending only). A filled button that refuses is a dead button wearing a coat.

도착 is a transition, not a record

Sean's 「click arrived」 opens ⑦ and does nothing else. return_arrived_at does not exist (zero hits in migrations; spec v2 §7.1 proposes it with three siblings). The record of a return is the two-sided stamp — session_confirm_return (0045:66-100, 0069:84) — which is shipped and which neither side can complete alone. Drawing 도착 as a stamp would have invented a column in the artifact used to decide.

ⓑ 도장 칸, in its literal role

His round-6 pick is the stamp vocabulary now, and it carries three different jobs here: the host's verify (③), the two sides of the ritual (⑦, F2) and the pass's 체크인 state (⑧⑨). No single-select choice arises across these three surfaces — the return branch is decided by pickup_mode at setup, not by the runner — so ⓑ appears as its square rather than as a choice row. The first real choice these screens grow takes ⓑ.

Address, drawn at the width the privacy scope allows

④ prints addresses.label and addresses.dong — 「집 · 반포동」 — and nothing else. dong is a real column (0122), classified there as 개인정보 at 동 granularity, not 위치정보. A 도로명 string would have been fabricated. The full address is what 길찾기 consumes, not what the screen prints.

Affordance count

① back + 3 exits + 종료 = 5 · ② back + 처리 = 2 · ③ back + 2 확인 = 3 · ④ back + 길찾기 + 도착 = 3 · ⑤ back + 다시 시도 + 채팅 + 도착 = 4 · ⑥ back + 채팅 + 호스트 창구 + 도착 = 4 · ⑦ back + 반환 확인 = 2 · ⑧ back + 체크인 = 2 · ⑨ back + 세션으로 = 2. Everything else — numerals, roster print, stamped rows, address lines, the two-sided sentences — carries no fill, no border, no chevron. Coral is one per frame at most, and ② ③ ⑨ carry none: nothing there is the user's turn.

One addition to the shared tap grammar

Measured on the rendered page: every tappable is ≥44pt except the map's .mastchip .back at 34pt — which is the world's own back control, byte-identical to the run lab's, inherited not introduced. Raising it is a shared-grammar change and belongs to whoever owns that decision, not to this file.

The labelled back control (.bkw — 「‹ 라이브 지도」, 「‹ 세션」) is new. A bare 34pt arrow says back; it does not say back to the map you were watching, and "leaveable and re-comeback-able" is the entire point of both ③ and ⑧⑨. Same border, same paper, 44pt, one word of destination.
