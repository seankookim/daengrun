FOpen questions — I could not decide these from the code

  1. Detail-screen title grammar is unspecified. §3b fixes the screen title at 30/900 Black Han Sans, but that was written for text-titled tab screens. Across this cluster the four pushed screens run 23/900 display (fitness masthead), 23/900 plain ink (report, review — deliberately, per report.tsx's comment) and 20/800 (dog). Three grammars, no rule. Should DESIGN.md gain a detail-screen title spec, and is it the 23/900 plain-ink one that report/request/review already share?
  2. Does the gold reservation bind to a review's stars? §8 says gold = milestone events only. B④ spends gold on a lifetime PR (clearly a milestone). But C①/C③ paint filled review stars in colors.gold #D9A93C — stars are conventionally gold everywhere on earth, and the current code already uses an off-token #f2c14e. Is a filled star a milestone use, an exempt convention, or should it be paper.pending/ink instead?
  3. Is the 하이 포인트 strip a deliberate lilac island or a world leak? §2 says never mix worlds within one surface; report.tsx's own comment calls it a quiet lilac receipt on purpose. B③ draws the paper version so both can be seen. This is a taste call I should not make alone.
  4. On a stopped run, may the coral 재예약 panel be demoted? RULING #11 put it there and made it the frame's one saturated element. B② argues G1 changed the meaning of that state (the owner now pays, so the owner audits). This needs your yes, and it is the only variant in the file that touches a standing ruling.
  5. Where does 주간 목표 belong? weeklyGoalKm is on DogProfile and editable only on fitness, with dog.tsx pointing there in copy. That is coherent, but the goal is a property of the dog, and the fitness stepper is the only editable control on an otherwise read-only report.   6. Android has no 반려견 추가. Alert.prompt is iOS-only; Android owners get 「iOS에서 지원돼요」, which is a dead end, not a feature gate. Fixing it needs a real inline field or sheet — small, but it is a new control and I did not draw it without a decision. Is Android in the Banpo pilot at all?
  7. 생일 has no picker and no dependency to build one. Nothing like @react-native-community/datetimepicker is installed, so D③ keeps the typed YYYY-MM-DD field and only moves its validation inline.
