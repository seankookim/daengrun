클럽 v2 — 러너 픽 Lab

OWNER PICK SURFACE · P2 ×3 · P3 ×1 · P4 ×1 · SEAN PICKS BY NUMBER

The v2 spec (§6, §10.1) hands the runner choice to the owner: at P2 the owner picks from the session's committed runners (or opens the 자동 연결 door), at P3 a 2-hour reply window runs while the runner decides, and at P4 the pairing stands with a server-quoted cancel and a re-specified objection door. This lab draws three anatomies of the P2 pick list (①②③) and one frame each for P3 (④) and P4 (⑤) — same data contract everywhere, different card personalities. Every frame is 390px so 1px = 1pt, every hex is already in app/src/theme.ts or club-ui.tsx, and the 14pt Korean floor is literal.

⚠ Two privacy laws are load-bearing, not styling

  • Never money. 재정 ④: the club fare speaks once, on the 승낙서. No pick card, pending card or paired card below carries a won amount — the single exception is the P4 cancel quote, which §5.4 ORDERS as a server-fetched exact figure (quote_club_cancel_fee), shown only at the cancel door.
  • Never distance-to-runner. Round-2 F7c: an owner who controls their own pin could triangulate a runner's home from repeated distance bands. Proximity exists only inside session_auto_pick's definer ranking. Cards render tier · pace fit · load/cap — nothing else.
Also: 「러너 변경 요청」 is legal vocabulary again under v2 — §5.5 re-specifies the objection as un-pair, never refund (runner cleared, seat kept), so frame ⑤'s door says exactly that.

P2러너 선택 · NEW pick surface · club/session/[sid].tsx owner card

The committed-runner list the owner picks from, plus the Mode C door. All three variants bind the same §9 board projection (runners[] → name · tier · pacePerKm · load · cap — the board exposes the SAME load the server enforces, §6.4) and the same two RPCs. What differs is card anatomy and commitment mechanics: ① per-card action, ② ticket cards with the pick as the stub, ③ compact rows with select-then-confirm. ② additionally draws the gated 자동 연결 state (no pinned address — §6.5's explicit gate, never a fabricated empty list).

①로스터 — per-card action

Roster list, one 지목 button per card. Fastest path: see a runner, tap their button, done — no selection state. Pace fit leads each card as a volt/amber tag with the raw pace beside it (declared, so the number is shown, not just the verdict). The full runner keeps their card but the button names the refusal (§6.4's consumed capacity) — the console's dead-button grammar, extended. 자동 연결 sits BELOW the list as a coral door: Mode B is the primary posture, C is the shortcut.

P3수락 대기 · pick-pending card + TTL ring · §6.3

The pick is out; the runner has 2 hours (🔵 RULED 14.1 — a pick issued <2h before the session clamps to scheduled_at). The DrainRing idiom carries the countdown — drawn only when the server gave proposal_expires_at, and an elapsed TTL says so instead of counting to 00:00 (the session shell's own rule). Withdrawing the pick is free (§6.2's widened session_proposal_revoke — without it this button is dead); cancelling the seat rides the quoted ladder and is deliberately a quiet second exit.

④대기 카드 — ring, honest expiry, free withdraw

One card, one clock, two exits of very different weight. The ring is the app's DrainRing (accent lit on amber well). Under it, the expiry contract is spelled before it happens: lapse returns the dog to P2, seat kept, owner notified. A small timeline shows what the system already did (push at issue) and will do (T−15min reminder) — bound facts, not decoration. 지목 취소 is a full-width secondary; 예약 취소 is a text link that leads to the quoted flow, never a fee surprise.

OPEN QUESTIONS — what the spec could not decide for this lab

  1. ①②③ — where does 자동 연결 live? ① puts it below the list as a coral door (C is a strong shortcut), ② above as a full door (C is read first, and its gate teaches the pin), ③ as a compact chip (C is an input, not a surface). The coral budget allows exactly one of these per screen — the answer decides which element on P2 gets the screen's single coral.
  2. Pace verdict bands. 잘 맞음 / 빠른 편 are the §6.5 30-sec buckets rendered as words, next to the raw declared pace. Show both (drawn here), verdict only, or numbers only? The verdict is derived; the number is a self-declaration (round-1 F11) — showing both is the honest middle but costs a line.
  3. ③'s CTA restates the 2h TTL before sending. ① and ② fire on one tap with no restatement, leaning on the free withdraw instead. Is the pick weighty enough to earn a confirm step, or is 무료 취소 the confirm?
  4. ⑤ — the unchosen pickup-mode chip. Drawn read-only for vocabulary. If Sean wants mode switching after pay, it becomes a control and needs the §5.3 fee copy on the spot; if not, the second chip could drop entirely and the card gets one line back.
  5. ④'s 예약 취소 link routes to the quote-first flow rather than quoting inline. Inline would put a won amount on the P3 card — legal under §5.4 but a second money surface. Keep the detour?
