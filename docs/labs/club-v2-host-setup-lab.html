Three control vocabularies for the same fields — pick the one that should ship

  1. ①세그먼트 — each choice is a row of plates and the pick turns one solid ink. Fastest to read, and the whole option set is visible at once; it costs vertical space per field and caps a choice at three options.
  2. ②목록 — ink-ruled rows with a stamp square. Scales to any number of options and puts the option's reason on the same line; a five-field screen becomes long.
  3. ③카드 — two-up plates carrying a line of consequence inside. Best where the choice has a meaning a host may not know (포맷 does); heaviest per field.

Say a number — ①, ② or ③. The fields, their values and their refusals are identical in all three; only what you touch changes. The lower half of every frame — 위탁 정원, 창, 픽업·반환 — is readouts in all three, because the host has no writer for them.

Half of this screen is a readout, and that is the finding

The obvious host setup screen has a dog-capacity stepper, a signup-window picker and a per-dog pickup/return control. All three would be dead. Measured, not assumed:

🔴 위탁 정원 — derived, not typed

_club_rederive_capacity (0037:47-57) sums delegated_capacity over committed runner assignments and writes club_sessions.delegated_dog_capacity itself; the per-runner cap comes from tier (certified 1 · veteran 2 · master 2, 0037:38-45). club_create_session has no argument for it. A stepper here would not merely be routeless — its value would be silently overwritten by the next runner who commits, which is worse than a dead button because it looks like it worked.

🔴 신청 창 — the column does not exist

Every alter table club_sessions in the repo was read (0047:14, 0048:76, 0050:241). There is no signup_opens_at, no signup_closes_at, no window column at all. Three windows are derived and none is set:

신청 마감scheduled_at itself — session_approve_dog raises session_closed past it (0043:264).
체크인scheduled_at − 2h … + 6h, projected as checkinOpen (0147).
지도_club_pack_window (0159) — the same band and someone actually checked in and the host has not ended the runs.

So 창 is printed, not picked. If Sean wants a settable signup window, that is a column, a CHECK, a refusal and a pin — a slice, not a control.

🔴 픽업·반환 — the owner's to write, and nobody writes it yet

The columns are real: session_dogs.pickup_mode ∈ owner_home|session_start, return_mode ∈ owner_home|session_finish (0129:186-191, NOT NULL, CHECK-named). Grepped across every migration and the whole client: only 0128 and 0129 mention them — there is no writer, so every row is owner_home by default and the monitor honestly shows one value.

⚠ A host control over these would be worse than dead. return_mode is the conjunct that stops booking_pickup_address handing an owner's home to a runner standing at the finish line (0128's Critical, fixed in 0129) — it is a privacy decision the owner makes about their own address. The host watches it; the host does not set it.

What the host genuinely writes

포맷owner_only · mixed · delegated_only — refuses bad_format.
시간≥ now + 1h, else too_soon (0037:372).
집결지NOT NULL, else meetup_required. The only always-present place string — route_id is nullable.
코스required unless 포맷 = 보호자만, else route_required — the fare is priced off km.
사람 정원CHECK 2–60, default 12. The stepper's bounds are the constraint's, not a guess.

Where each vocabulary breaks

①세그먼트 caps at three plates. 포맷 fits exactly; a fourth format would force a redesign.
②목록 is the only one that scales, and the only one where the readouts and the controls share a grammar — which is also its risk: the two must stay visibly different, so controls carry the stamp square and readouts carry none.
③카드 teaches 포맷 best and costs the most height; it is drawn with 위탁만 pushed into a secondary list rather than a third card.

Not this lab's screen

The owner's setup flow — 직접 달리기 vs 러너 요청 → 픽업 → 세션 상세 → 반환 — is docs/labs/club-v2-setup-lab.html (r5) and stands unchanged. That screen is where pickup_mode/return_mode get written; this one is where they get watched.
