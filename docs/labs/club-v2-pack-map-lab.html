The counter is real and unreadable, and both halves matter

Sean ruled 「Yes, add counter」 and 0160 built it — as an instrument. pack_map_roster_reads (0160:436-445) is RLS-on with zero policies and revoke all … from anon, authenticated. Its own comment: 「nothing reads it but a human with a psql prompt」. No RPC returns it, no view exposes it, no client touches it.

So the value slot is 「—」 in every variant. Printing a number would be the fabrication law's central case; printing nothing would hide the decision Sean is being asked to make. The placement is pickable today; the number needs one small server ask — a definer returning the current session's two integers, with whatever gate Sean wants on it (host-only is the obvious one, and it is a genuine choice: the count is a fact about strangers).

🔴 It counts OPENS, not watchers

One integer per (session, anon|authed, KST day), incremented on every club_pack_map_roster call (0160:509-514). It cannot answer 「who」 or 「when within the day」 — 0160:423-428 argues that inability is the privacy guarantee. Therefore:

거짓「7명이 보고 있어요」 — not concurrency, not people, not even distinct devices.
참「오늘 연 횟수」 — which is the string all three variants use.

② prints the 익명/로그인 split because that is the question the pilot actually has (does a shared link bring in people without accounts); ①③ print one number and lose it. That trade is part of the pick.

The runner icon means WORKING, not IS-A-RUNNER

isRunner (0160:530-538) is true when session_people.role ∈ (host_runner, handling_runner, runner_attending) or the person is responsible_profile_id for at least one delegated dog in this session. A certified runner who came along as an owner draws no icon. The strip's role line (「담당 러너」 / 「보호자 동반」) is the raw role value, not a re-derivation — 0160 says so explicitly.

The masthead title is a server fact

clubName was added by 0160 for exactly this element (codex #10): the map previously titled itself from a URL parameter, so a deep link could put any string above someone else's walk. It is returned whether or not the window is open, because the masthead has to say something before the walk starts.

⚠ The clock correction is invisible and load-bearing

Every marker's at is now stamped by the server (0160 §A), so the viewer's own skew is the single point of failure. serverNow exists so the screen can compute offset = serverNowMs − Date.now() and judge freshness on the corrected clock. Without it a phone 15 s slow sees every marker as future-dated, the freshness rule refuses them all, and the map is empty with nothing on screen explaining why. Whichever variant ships, that subtraction ships with it.

Why 「아직 시작 전이에요」 and not an error

_club_pack_window (0159) is a conjunction of four facts, and three of them are ordinary: the session is open or full; now is inside scheduled_at − 2h … + 6h; somebody has actually checked in; and the host has not ended the runs. A closed window is therefore the normal state for most of a session's life, and it has four different causes.

The copy names the one a person can act on — 「첫 체크인이 찍히면」 — and the band, which is a fact. It does not say 「불러오지 못했어요」, because nothing failed. ⚠ A genuine failure has its own vocabulary: the publish side's refusals are a closed set (not_signed_in · not_checked_in · window_closed · bad_position · too_fast · not_delivered) precisely so each maps to a sentence a person reads, and not_found is matched by message string in fetchPackRoster — so that token is part of the contract and must not be reworded.
