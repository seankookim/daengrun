### 1.3 그리드 아키텍처

**단계 1 — 런칭 9컷 (D02–D04).** `campaign-concepts.md §1.5` 그대로. 발행 순서는 **9 → 2**, 그리고 **1번(매니페스토)은 D08까지 보류한다.**

```
발행 후 D04 시점 (8컷)      D08 리빌 직후 (9컷 완성)
[2 발]  [3 신발] [4 위상차]   [1 매니페스토][2 발]   [3 신발]
[5 그림자][6 한줄] [7 POV]     [4 위상차]  [5 그림자][6 한줄]
[8 COIN][9 STAIR]  ·           [7 POV]    [8 COIN] [9 STAIR]
```

이게 티저의 장치다. **8컷 상태에서 그리드는 한 칸씩 밀려 있어 컴포지션이 성립하지 않는다** — 발 옆에 신발이 안 오고, 펄스 레일 밴드가 중앙 행에 안 걸린다. 보는 사람은 "뭔가 안 맞는데"까지만 느낀다. D08에 매니페스토 1컷이 올라가는 순간 전체가 제자리로 스냅되고, 그때 처음으로 프로필이 하나의 그림이 된다. 리빌이 카피가 아니라 **레이아웃으로** 일어난다.

**단계 2 — 9컷 이후 그리드 리듬 규칙 (D08~).** 9컷은 소모품이 아니라 자산이므로 아래를 밀려나는 속도까지 계산해서 지킨다.

1. **3의 배수 규칙:** 매 3번째 포스트는 **타입 타일**(크림 또는 forest 단색 + Black Han Sans 한 줄). 사진이 연속 6칸 이상 붙으면 그리드가 반려견 계정처럼 뭉개진다. 타입 타일이 호흡이자 브랜드다.
2. **다크 앵커 1/9:** 한 화면(9칸) 안에 forest 풀블리드는 **정확히 하나.** 두 개면 무겁고 0개면 앵커가 없다.
3. **신뢰 표면은 항상 크림:** `F6 뛰기 전에` 시리즈는 전부 크림/clay 단색 카드 → 그리드에 밝은 칸이 주 1회 규칙적으로 생긴다. 이게 우연이 아니라 시스템으로 보이게 하는 장치.
4. **러너 방언은 그리드가 아니라 릴스·스토리에서:** 그리드 방언비는 보호자 8 : 러너 1을 유지. 러너 콘텐츠는 릴스로 나가고, 릴스 커버는 그리드 톤에 맞춰 크롭한다(§2 캘린더에서 릴스 커버 지정).
5. **마스코트는 그리드에 없다.** 마스코트가 허용되는 곳은 스토리 빈 상태 · 인앱 온보딩/스탬프 · 굿즈뿐이다. **프로필 사진·하이라이트 커버·피드 포스트에는 쓰지 않는다** — 하이라이트 커버 4장은 §1.4대로 타입·글리프·실루엣으로 간다. (ECD 정정: §1.1의 "하이라이트 커버·빈 상태에만"과 이 규칙이 서로 달라 마스코트가 신뢰 표면에 올라갈 여지가 있었다.)
6. **릴스와 그리드의 관계 — 티저 주간만 예외:** 릴스는 기본값으로 프로필 그리드에 들어간다. **D01–D07 릴스(D06·D07)는 "프로필 그리드에 표시"를 끈다** — 안 끄면 8컷이 두 칸 밀려 §1.3 단계 1의 스냅 장치가 통째로 무너진다. 앱 버전에 그 옵션이 없으면 두 편을 **스토리로만** 내보내고 D08 이후 릴스로 재발행한다. **D08 두 개의 심장 필름은 예외 — 그 릴스가 곧 1번 칸이다.** D08 이후 릴스는 그리드에 그대로 들어가고, 그때부터는 위 1–4번 리듬 규칙이 릴스 커버에도 동일하게 적용된다.

4개로 고정한다. 5개 이상이면 1인 운영으로 관리가 안 되고, 프로필 상단에 스크롤이 생기면 첫 화면에서 CTA가 잘린다.

운영 규칙:
- **FAQ 하이라이트가 곧 CS 시스템이다.** DM으로 같은 질문이 2번 오면 그날 안에 FAQ 스토리 한 장을 만들어 넣는다. 3번째부터는 링크로 답한다.
- 하이라이트 커버 4장은 **런칭 전에 한 번에 제작**(§6 배치 1). 나중에 만들면 영원히 안 만든다.
- "러너 1기"와 "FAQ"에만 링크 스티커. "크루"·"체력나이"에는 링크를 넣지 않는다(파는 표면과 신뢰 표면 분리).
- 하이라이트에 **AI 이미지 금지** — 하이라이트는 상설 정보 표면이라 "콘셉트"라는 캡션 단서가 사라진다.

## PART 3 — 해시태그 시스템

### 3.1 원칙

1. **포스트당 8–15개.** 30개는 스팸 신호이고 0–3개는 발견 포기다.
2. **캡션 본문 안**에 넣되, 본문과 줄바꿈 3줄로 분리. 첫 댓글 분리는 이점이 없고 편집 시 유실된다.
3. **세트 3개를 로테이션.** 동일 블록을 연속 2회 쓰지 않는다.
4. 세트당 구성 = **브랜드 2–3 + 대형(10만+) 2–3 + 중형(1만–10만) 3–5 + 로컬/니치 2–3.** 대형만 쓰면 3초 만에 묻히고, 니치만 쓰면 도달이 없다.
5. **한국어 태그 우선.** 영문 태그는 러너 방언에서만(#running #canicross), 세트당 최대 2개.

### 3.2 세 개의 로테이션 세트

**SET A — 보호자 / 발견 (12개)**
```
#도그스하이 #산책말고러닝 #반려견운동 #강아지운동량 #고에너지견종
#보더콜리 #웰시코기 #리트리버 #대형견 #멍스타그램 #독스타그램 #한강댕댕이
```

`[런치동]` 자리는 확정된 동 이름으로 치환(예: `#반포동`, `#성수동`). 로컬 카페·맘카페 인접 태그가 이 세트의 핵심 — 도달은 작지만 전환은 여기서 나온다.

### 4.2 협업 게시물(collab) 활용

인스타 협업 게시물은 **양쪽 그리드에 동시에 뜨고 도달·좋아요·댓글이 합산**된다. 우리가 가진 유일한 무료 도달 증폭기다. 초대는 신중하게 — 상대가 수락 안 하면 그냥 우리 포스트가 된다.

| 대상 | 콘텐츠 | 시점 |
|---|---|---|
| 파트너 러닝크루 | 크루 테이크오버 토요일 런 (월 1회) | D27 이후 매월 |
| 1기 인증 러너 개인 | **CERT DAY 세트** — 러너 본인이 주 소유자, 우리가 협업자 | 기수 인증일 (D29) |
| 로컬 동물병원 | "뛰기 전에" 안전 프로토콜 1편 (수의사 자문 확보 후에만) | W4 이후 |
| 마이크로 멍스타그래머 (5k–50k, 로컬) | 첫 무료 러닝 후 본인 콘텐츠 | 서비스 시작 후 |

**규칙:** 협업 게시물에 **우리 CTA를 넣지 않는다.** 상대 오디언스 앞에서 파는 순간 다음 협업이 없다. 전환은 프로필 방문 → 바이오 링크로 받는다.

### 4.3 견스타그램 서식 참여 + 자체 서식 발명

한국 반려견 인스타는 **서식(릴레이 템플릿) 문화**가 살아 있다. 여기 참여하는 게 아니라, 우리 것을 하나 만들어 돌린다 — 참여는 1회성이고 발명은 자산이다.

**「우리 개 에너지 서식」 — 5문항, 스토리 템플릿 (volt/forest, 빈칸 5줄)**
```
① 이름 / 견종 / 나이
② 하루 운동 시간
③ 밤 11시에 하는 짓
④ "산책으론 안 빠져요" 몇 점 / 10점
⑤ 우리 애가 뛰면 몇 km쯤 갈 것 같은지
— 채워서 @dogs.high 태그, 3명 지목
```
- 발행: **D14 스토리** (C6 죄책감 해소 포스트와 같은 날 — 감정이 열린 직후에 참여율이 가장 높다).
- ④번이 이 서식의 목적이다. 포지셔닝 문서의 1차 타깃 정의("우리 애는 산책으론 안 빠져요")를 **응답자가 스스로 말하게 만든다.** 8점 이상 응답자는 전부 개별 DM 대상 = 창립멤버 리스트.
- 리포스트 규칙: 들어온 응답은 전량 스토리 리포스트(24시간 내), 하이라이트엔 안 넣는다.
- 기존 서식(견종 소개 서식 등)에는 **창업자 개인 계정으로만** 참여. 브랜드 계정이 남의 서식을 도는 건 브랜드 격을 깎는다.

### 4.4 UGC 태그 규칙

**하나의 규칙만 반복한다:** `배번호 + @dogs.high`

이벤트 배번호에 인쇄되는 문구(피니셔 포토 배송 메시지·현장 배너에도 동일 문구):
```
사진 올릴 때 배번호가 보이게, @dogs.high 태그해주세요.
태그해주신 사진은 저희 계정에 올릴 수 있습니다 (원치 않으시면 DM 주세요).
```

- **배번호가 보이는 것**이 규칙의 핵심이다. 배번호는 (a) 프레임 안의 유일한 volt 요소라 우리 포스트로 읽히고, (b) 어느 회차인지 추적 가능하고, (c) 배번호를 찍으려면 개를 제대로 찍어야 한다 → UGC 품질이 올라간다.
- 리포스트 시 **항상 원 작성자 멘션 + 스토리 우선.** 피드 리포스트는 서면(DM 텍스트) 동의 후에만.
- **UGC를 후기로 쓰지 않는다.** 고객 0인 상태에서 이벤트 참가자 사진은 사회적 증거가 아니라 참가 기록이다. 캡션에 "후기", "만족", "추천" 금지.
- 태그 대시보드: 주 1회 태그됨 탭 + `#도그스하이` 확인. 누락 없이 24시간 내 반응.

### 4.5 dogshigh.kr — 프리런치 단 하나의 임무

**임무: 인스타에서 온 사람을 두 개의 폼 중 하나에 넣는다. 그 외 전부 삭제.**

```
┌──────────────────────────────┐
│  (forest 풀블리드, 워드마크)      │
│  한 번의 러닝, 두 개의 심박.       │
│                              │
│  [ 1기 러너 지원하기 ]  ← volt   │
│  [ 창립멤버 사전등록 ]  ← 아웃라인 │
│                              │
│  (스크롤: 인증 기준 4개 · 정직한   │
│   계산 표 · 안 뛰는 기준 · FAQ)   │
└──────────────────────────────┘
```

- **버튼은 2개. 세 번째 버튼은 없다.** 앱 다운로드, 뉴스레터, 문의하기 전부 프리런치엔 없다. 세 번째 선택지는 전환율을 깎는 게 아니라 두 폼의 데이터를 오염시킨다.
- 상단 폴드에 **버튼 2개가 다 보여야 한다.** 러너와 보호자를 첫 화면에서 분기시키는 게 이 페이지의 전부.
- 폼 필드 최소화: 러너 = 이름/연락처/주 러닝 지역/5km 기록(선택)/크루 소속(선택). 보호자 = 이름/연락처/거주 동/견종·나이/"우리 애는 산책으론 안 빠지나요" 1–10.
- **UTM 필수:** `?utm_source=ig&utm_medium=bio` / `=story` / `=post&utm_content=[컨셉ID]`. 스토리 링크 스티커에도 매번 붙인다 — 안 붙이면 §5의 지표가 통째로 무의미해진다.
- 페이지에도 정직성 룰 적용: 서비스 시작 시점 명시, 수익 보장 문구 0, 체력나이 = 자체 지표 표기, 고객 후기 섹션 **없음**(없는 걸 비워두면 그 자체가 신호다 — 자리를 만들지 말 것).

## PART 5 — 프리런치 지표

### 5.1 팔로워 수는 KPI가 아니다 — 명시적으로

30일 후 팔로워가 400명이든 4,000명이든 **의사결정이 하나도 안 바뀐다.** 우리가 파는 건 런치 동 반경 2km 안의 개 50마리와 러너 30명이고, 팔로워는 이 둘과 상관이 매우 약하다. 팔로워 수를 목표로 두는 순간 콘텐츠가 전국구 밈으로 흐르고, 그 계정은 서울 전역에서 예약이 안 되는 서비스를 광고하게 된다.

팔로워는 **관찰만 한다.** 목표도, 보고 지표도, 축하 대상도 아니다.

### 5.2 단 하나의 퍼널

```
노출 → 프로필 방문 → 링크 클릭 → 폼 제출 → (러너)페이스 테스트 / (보호자)이벤트 참가
```
