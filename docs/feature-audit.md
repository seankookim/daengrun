## 8. 커넥터 목록 (필요해질 순서대로)

2. **Kakao OAuth** — 로그인
3. **Expo Notifications** — 푸시
4. **react-native-maps + expo-location** — 실지도·트래킹
5. **카카오 알림톡** — 한국 표준 예약 알림 채널 (푸시 미수신 보완, 노쇼 감소에 직접 효과)
6. **토스페이먼츠 or 카카오페이** — PG
7. **PASS 본인인증** — 러너 KYC
8. **기상청 + 에어코리아 API** — 날씨/미세먼지 규칙
9. **안심번호 (번호 마스킹)** — NHN/세종텔레콤 계열 (Twilio는 한국 070 제약)
10. **채널톡** — CS
11. **Sentry + 분석(PostHog/Amplitude)** — 빌드 배포 시점에
12. 오픈뱅킹/정산 대행 — 정산 자동화 (파일럿은 수기 이체 가능)

## 9. 전략 결론: 백엔드 전에 이걸 다 만들어야 하나?

**아니다. 4가지만 예외.** 판단 기준: *"이 기능이 데이터 스키마를 바꾸는가?"*

- **스키마를 정의하는 것 → 백엔드 전/동시 목업** (안 하면 테이블을 두 번 만든다):
  1. **러너 지원 퍼널** — runners 테이블·인증 등급·서류 스토리지 구조를 결정
  2. **양방향 리뷰** — reviews 테이블이 단방향으로 굳으면 마이그레이션 고통
  3. **러너 수익 탭** — payouts·ledger 구조 결정
  4. **주소록** — addresses 테이블 + 공동현관 암호화 필드
- **백엔드가 있어야 의미 있는 것 → 지금 목업 금지** (푸시, 실시간 채팅, 결제, 신호끊김, 강제 알림): 타이머 가짜를 더 쌓아봤자 스키마에 기여 없음
- **코드가 아니라 문서인 것 → 지금 작성** (비용 0): 분실 프로토콜, 노쇼 정책, 날씨 규칙, 응급 이송 동의, 제3자 사고 대응 → `docs/policies.md`
- **어드민 → 파일럿은 도구 없이** Supabase Studio + 시트. 정식 어드민은 PMF 신호 후

**권장 순서**: ① 스키마 결정 4종 목업 (1세션) → ② Supabase 스키마+auth+상태머신 → ③ EAS/TestFlight → ④ 지도·위치 실화 → ⑤ 푸시+알림톡. 인터뷰·러너 리크루팅은 이와 무관하게 병행.
