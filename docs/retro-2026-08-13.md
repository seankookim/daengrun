## 2. The eight collisions, and the arc

Ordered as they happened:

1. **0078 ×3** — three sessions, three files, one number.
2. **0081 ×2** — same shape, one hour later.
3. **`/tmp/dr85` ×2** — two sessions derived a *temp harness directory* from the migration
   number, and deleted each other's postmaster mid-run. It presents as a migration file
   vanishing during an apply: it looks exactly like disk corruption.
4. **0082 ×2** — number claimed while another session's build agent was mid-write.
5. **0083 ×2 (the double-yield)** — both sessions politely yielded the number to the other and
   both moved to 0084. *Deference produced its own collision.*
6. **0086 — a pushed FILE with no ledger ROW.** The rule said "a number is claimed when it's on
   origin", and the file WAS on origin — only the row wasn't. A newly-started session was told
   0086 was free.
7. **0089 ×2 — rows with no files.** The exact inverse of #6, and the pre-push hook is
   structurally blind to it: the hook refuses a push that *introduces* a colliding number, and
   neither file had been pushed.
8. **`pkill -f postgres` matched SEVEN processes.** `harness.sh` exported a *relative*
   `PGDATA=./.pgtest/data`, so every session's postgres command line was byte-identical. One
   session clearing its own stale postmaster killed everyone's.

**Is the "sessions racing → automating the referee → no identifier at all" arc real?** Partly.
The first five are genuinely one class: *a shared machine plus an identifier that is not unique.*
Collision seven is different in kind — an automated merge resolver deduped REGISTRY rows by
migration number and silently ate a live claim. That one only became possible *because* the
pre-push hook existed: a guarded push made it feel safe to let a tool settle the ledger.
**A guard on one step invites delegation of the next.** That is the sharpest predictive line the
day produced.

**Every correct fix made the identifier unique at the source** rather than asking people to be
careful with it:

| collision | non-unique identifier | fix |
|---|---|---|
| numbers ×5 | "next free", computed per-session | claim row on origin + pre-push hook |
| `/tmp/dr85` | temp dir named after the *migration* | name it after the *session* |
| `pkill -f` | relative `-D` in the postgres command line | absolute `PGDATA` |
| duplicate work ×2 | no identifier at all for unnumbered work | an in-flight claim table |

## 3. Five artifacts that read as authoritative without being verified

This is the day's second class, and it is subtler than the first because **nothing looked wrong.**

1. **A build checklist that read well** — enumerated six properties of a two-party state machine;
   one was false (it claimed the machine self-heals a crash between stamp and effect; it detects
   and escalates). Written from a description rather than from the source.
2. **A suite at 475 green pins** that missed two blockers. The session's own post-mortem:
   *"both pins measured the symptom the design intended and stopped one question short."*
3. **A commit message asserting a property** — mine, claiming a grep returned nothing. I never
   ran it against trunk. It didn't.
4. **A code comment claiming a guarantee** that nothing enforced.
5. **A broadcast of "next free" from the coordinating session** — accurate when read, stale when
   sent, three times. Their own framing: *a number relayed by me is a stale cache carrying an
   announcer's authority, which is worse than no number, because it stops people checking.*

**The common structure: each artifact's FORM implies verification its CONTENT never underwent.**
A checklist implies someone checked. Green implies covered. A commit message implies done. None
of them were vague — vagueness gets questioned. **Precision without verification is
indistinguishable from precision with it**, which is why it travels further and lands harder.

**And every rule recorded today was broken by its own author within hours.** "Unpushed reserves
nothing" — by the session whose queue lived only in a conversation. "Verify, don't relay" — by me,
in a commit message, in the same hour I wrote the rule. "Numbers come from the file, never a
message" — by the announcer, three times. **That is not an argument against the rules. It is the
argument for mechanisms over discipline**, and it is why the pre-push hook is the most valuable
artifact of the day: it is the only one nobody can violate by being briefly confident.

## 4. The join nobody tests

The same structural bug appeared at four layers. In each, both sides were individually
well-tested and the *seam* was not, because each side's test replaced the other side with a fake.

| layer | what broke | why both sides stayed green |
|---|---|---|
| suite ↔ shipping path | a pin tested a helper; the code that ships calls something else | the helper genuinely works |
| TS ↔ SQL literal | a marker string duplicated across languages (`owner_cancel_late`) | each side asserted *its own* copy |
| client ↔ database | a column-grant migration didn't grant `SELECT` on `role`, which an `ON CONFLICT … SET role = EXCLUDED.role` arm needs | the grant was correct for every read; the *write path* consulted it |
| **deployed schema ↔ code** | the one that actually reached production | nothing local can see it |

**The repair the repo converged on, and it generalises: don't synchronise the copies — delete the
duplication.** Let one side own the fact, and have the other **read it at test time and verify
against it, in both directions.** No shared constant, no cross-language import, and it works with
the existing fakes untouched. In use now for two contracts (the cancel-tier marker, the
notification routing key), each mutation-verified to redden from either side.

⚠ **Its precondition is easy to lose:** it holds only while the owning side stays the *only* copy.
The moment the reading side caches the value in a constant — which looks like tidying and would
pass review, because hoisting a repeated string is normally correct — the test passes against the
copy and the join reopens. Both contract tests now carry a comment saying exactly that, because
**the test cannot defend its own premise.**

## 5. The one failure with no mechanical fix

⑫'s memo carried Sean's ruling in three places while its status line still read *"🟡 OPEN — needs
Sean's ruling."* The set's own convention is *read the status line, not the body* — which makes a
stale status line **the one artifact everybody trusts without checking.** A reader would have
concluded he owed an answer he had already given.

It was caught by another session reading it against the body. Not by a test, not by a failure.
The follow-up sweep of all thirteen memos then found two more saying *"Buildable"* long after
their code had shipped.

Every other class today got a guard. This one gets a habit: **when a memo changes, change line 3
first** — and record *ruled / built / deployed* as three separate facts, because only the third
tells anyone it is real for users.

## 3 things that worked

1. **Cross-session adversarial review.** Every real defect today was found by someone auditing
   something they did not write. The ops-alert leak, the checklist's false property, my false
   commit message, the stale status line, the `anon`-executable trigger. Not one was found by its
   author.
2. **Applying a lesson reflexively.** Twice, a session turned its own new rule on its own fresh
   work and found a defect within the hour. That is a higher yield than applying it outward.
3. **Refusing to decide.** Codex answered three ⑫ questions and explicitly declined the fourth.
   A build session refused to invent a points number Sean had not set. Both refusals saved work:
   his eventual answers were "reward was about tone" (no currency at all) and a work-gate that
   made the refused question moot.

## 3 things to improve

1. **The registry needs a third guard.** It covers file-vs-file and row-vs-row, and collision
   seven slipped through the gap between them. A pre-push check that a claimed row has a file
   *or* a stated intent would close it.
2. **Deployed-state drift is now the live gap.** With the schema in production, `ruled / built /
   deployed` are three facts and the memos track two. The sweep found status lines stale by hours;
   after a deploy they will go stale by days.
3. **Session identity is invisible in git.** 193 commits, one author, five sessions. Attribution
   lives only in commit-message prose. A trailer naming the session would make every future retro
   sharper at zero cost.

## 3 habits for tomorrow

1. **Claim before you edit a shared surface** — path-keyed, with `exclusive` or `shared`. It cost
   ten seconds each time today and would have prevented two duplicated hours.
2. **When a claim is unanswerable, look for the stronger question that is answerable.** "Which
   client build is live?" had no local answer; "what has *every* build ever read?" did, and
   dissolved the question instead of answering it.
3. **Change line 3 first.** Status before substance, every time.
