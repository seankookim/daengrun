# 위치정보법 검토 요청 — 댕런 (반려견 러닝 매칭 서비스)

**변호사 상담용 · 문의: 김세안 (창업자)**

> **2026-08-27 발송 전 재검증에서 세 곳이 사실과 달라져 본문에 표시했습니다** — 제2-bis항(실시간

## 서비스 개요
보호자가 앱으로 러너(달리기 대행인)를 예약하면, 러너가 보호자의 반려견을 데리고 달립니다.
서울 반포 일대 파일럿 준비 중이며 **아직 정식 출시 전**입니다. 현재 실결제 없음(무료 파일럿),
법인/사업자 등록 준비 단계.

## 위치정보 관련 사실관계 (기술적으로 확인된 내용)
1. **러닝 중 러너의 GPS 위치를 수집**합니다. 화면이 꺼져 있어도 기록되도록
   **백그라운드 위치 권한**(iOS `location` background mode)이 앱에 설정되어 있습니다.
2. 러닝 중 위치는 **실시간 채널로 보호자 화면에 전송**되며, 이 실시간 전송분은 **서버 DB에
   저장되지 않습니다**(채널 전용). 서버에 저장되는 것은 **러닝 종료 후의 이동 경로(좌표열)**입니다
   (제4항). 제공(제19조)과 보유(제23조)를 분리해서 봐 주시기 바랍니다.
   ⚠ **2-bis. 다만 2026-08-19 측정 결과, 이 실시간 채널은 현재 사실상 공개 상태입니다.** 로그인하지
   않은 제3자가 앱의 공개 키와 예약 ID만으로 러너의 실시간 위치를 수신할 수 있고, 반대로 허위
   위치를 주입할 수도 있음을 실행으로 확인했습니다. 예약 ID는 오픈 풀에서 해당 예약을 본 모든
   러너에게 노출됩니다. **즉 당시 구조에서 "제공 대상은 해당 예약의 보호자"라는 설명은 사실과
   달랐습니다.**
   ✅ **2026-08-27 갱신 — 이 결함은 수정 완료되었습니다.** 작성 시점에는 「수정 작업이 진행 중」
   이라고 적었으나, 2026-08-27 재측정 결과 (ㄱ) 클라이언트가 채널을 비공개로 열고
   (`REALTIME_PRIVATE = {config:{private:true}}`), (ㄴ) 서버의 `realtime.messages`에 권한 정책
   3건(`run channel read` · `run channel write` · `party channel read`)이 실제로 존재합니다.
   **다만 위 25일간의 노출 사실 자체는 소급해 없어지지 않으므로, 제6번 질의(통지·신고 의무)는
   그대로 유효합니다.**
   ⚠ **데이터 저장 위치는 국내입니다.** 프로젝트 리전은 `ap-northeast-2`(AWS 서울)로
   측정 확인했습니다 — 이 문서의 이전 판은 "해외 리전"이라고 적었으나 **사실과 다릅니다**.
   다만 **저장 위치(국내)와 처리자의 국적(Supabase Inc., 미국 법인)은 별개의 사실**이므로
   두 가지를 모두 전달합니다. 국외이전(개인정보 보호법 제28조의8) 해당 여부는 변호사님의
   판단이 필요한 지점이며, 저희가 "국외이전이다/아니다"를 단정하지 않습니다.
3. 러너는 회원가입한 **특정 개인**(식별된 자연인)입니다. 즉 "식별되는 개인의 위치정보"입니다.
4. 러닝 종료 후 이동 경로(좌표열)는 서버에 보관됩니다. 코스로 공개할 때 **각 좌표의 시각
   정보는 제거**됩니다. ⚠ **다만 공개되는 코스 레코드 자체가 해당 러닝의 식별자·러너 식별자
   (개인)·승인자·러닝 종료 일자를 함께 보유하며, 이들 항목은 현재 비로그인 상태에서도 조회
   가능합니다**(2026-08-19 측정). 아직 실제로 공개된 코스는 없습니다(전 항목 NULL, 공개는 수동
   관리자 작업). 공개 전 차단 예정이나, 사실관계로 전달드립니다.
5. 현재 동의 절차: **OS 권한 팝업**과, 그 앞에 놓인 **앱 내 설명 화면 1장**입니다.
   ⚠ **2026-08-27 갱신 — 작성 당시에는 「OS 권한 팝업뿐」이었으나 이후 변경되었습니다.**
   설명 화면은 위치를 왜 받는지(거리 측정·보호자에게 실시간 지도)와 「러닝 중에만 사용하고,
   끝나면 멈춰요」를 고지한 뒤 OS 팝업을 띄웁니다. **정확히 하자면 이 화면은 코드에 반영되어
   있을 뿐, 앱이 아직 정식 출시 전이므로 실제로 이 화면을 본 이용자는 없습니다.** 또한 현재
   보호자 가입 흐름에만 있고 러너 가입 흐름에는 없습니다.
   **여전히 없는 것:** 위치정보 수집·이용에 대한 **별도 법정 동의서**, **위치기반서비스
   이용약관**, **개인위치정보 처리방침**. 위 설명 화면은 고지이지 법정 동의 절차로 설계된 것이
   아니며, 이것이 법정 요건을 충족하는지는 제3번 질의의 대상입니다.
6. 방송통신위원회(KCC) **위치기반서비스사업자 신고: 미신고** 상태입니다.

## 질문 (우선순위 순)
1. 위 서비스 형태가 **위치기반서비스사업자 신고 대상**인지, 신고가 **서비스 개시 전**
   완료되어야 하는지. (파일럿/무료/소규모라도 예외가 없는지)
2. 신고 대상이라면: 절차, 소요 기간, 필요 서류, 그리고 **사업자등록·법인 설립과의 선후 관계**.
3. OS 권한 팝업 외에 **별도의 위치정보 수집·이용 동의**와 **위치기반서비스 이용약관**이
   필요한지, 필요하다면 최소 요건.
4. 러너(위치정보 주체)와 보호자(열람자) 관계에서 추가로 요구되는 고지·동의가 있는지.
5. 미신고 상태로 파일럿을 진행할 경우의 **법적 리스크 수준**(형사처벌 여부 포함).

6. 위 제2-bis항과 같이 **제3자가 개인위치정보를 수신할 수 있는 상태가 존재했던 경우**, 실제
   접근 사실이 확인되지 않더라도 **유출 통지·신고 의무**(위치정보법·개인정보 보호법 제34조)가
   발생하는지, 발생한다면 기산점과 기한은 언제인지. 현재 접근 로그상 실제 수신 사례는 확인되지
   않았습니다.
   **노출 범위(2026-08-19 측정, 프로덕션 DB 직접 조회):** 해당 채널이 공개 상태였던 기간은
   2026-07-25(라이브맵 출시) ~ 2026-08-19(차단)까지 25일입니다. 이 기간 실제로 채널을 통해
   위치정보가 전송된 러닝은 **총 9건(2026-07-28 ~ 08-11)**이며, **9건 전부 러너와 보호자가 동일
   계정**(창업자 본인의 테스트 계정 `s4kim2025`)입니다. 즉 **제3자의 개인위치정보가 채널에 오른
   사실은 확인되지 않습니다.** 다만 실제 접근 로그는 없으므로 "누군가 수신했는가"는 확인 불가이며,
   위 사실관계 하에서 통지·신고 의무의 발생 여부와 기산점을 여쭙습니다.

## 함께 여쭤볼 별건 (결제 관련, 1문항)
자동결제(빌링키) 도입 시, **결제 전 사전 고지 의무**(금액·시기 통지)의 구체적 요건 —
전자상거래법/여신전문금융업법상 무통보 자동결제가 허용되는 조건이 있는지.


## 추가 질의 (2026-08-25) — 요청 목록의 '출발지까지 거리' 표시

**사실관계.** 러너가 아직 수락하지 않은 예약 요청 목록에, 러너 현재 위치에서 픽업 지점까지의
거리(구간 밴드, 미터 원값 아님)를 표시하는 기능이 제품 결정으로 승인되었습니다. 픽업 좌표는
서버 밖으로 나가지 않으며(밴드만 반환), 러너 좌표는 저장되지 않는 설계입니다(STABLE 함수,
입력 격자 양자화로 다변측량 차단). 그러나 **러닝 중이 아닌 시점에 러너 단말의 위치를 서버가
1회 처리**하게 됩니다.

**질의.**
1. 개인정보처리방침 **초안**의 문장 — ⚠ **2026-08-27 정정: 이 문서의 이전 판은 「현재 공개된」
   이라고 적었으나 사실과 다릅니다. 이 방침은 사내 초안(`docs/legal/privacy-policy.md`)이며
   아직 어디에도 게시된 바 없습니다.** — 「러닝이 시작된 시점부터 종료 시점까지만 수집합니다.
   러닝 중이 아닐 때는 위치를 수집하지 않습니다」 — 하에서, 요청 목록 열람 시의 1회성 위치
   처리(저장 없음, 즉시 폐기)가 이 문장과 양립합니까? 양립하지 않는다면 방침 개정 문안은?
2. 저장 없는 1회 처리도 위치정보법상 '수집'에 해당하여 별도 동의 게이트(제15조/제18조)가
   필요합니까? (현재 러너의 위치 동의는 OS 권한 대화상자뿐이라는 사실은 본 브리프 제2항과
   readiness-review-2026-08-19.md에 기재.)
3. 대안으로 러너의 '홈 베이스' 좌표를 저장해 거리를 계산하는 경우: 개인위치정보의 보관으로서
   1년 보관 상한(시행령 제26조의2)과 파기 절차 의무가 발생합니까? (파기 인프라는 0120 슬라이스에
   PARKED 상태로 존재.)
4. 픽업 주소의 법정동(동 단위 라벨)을 수락 전 러너에게 표시하는 것은 별도로 진행 중이며, 이는
   위치정보가 아니라 동 단위 개인정보로 분류했습니다 — 이 분류에 이견이 있으시면 알려주십시오.
