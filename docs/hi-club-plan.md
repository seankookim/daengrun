# 하이클럽 + 글로업 머지 — 마스터 플랜 (2026-07-29, Sean 피드백 기반)

정본 문서. 글로업 랩(docs/design/glowup-lab.html) 피드백으로 확정된 UI 머지 스펙과,
하이클럽(동네 그룹런) 시스템 설계·페이즈 분할·결정 필요 사항.

## 1. 확정 UI 머지 (로직 무변 — 바로 구현 가능)

### 1-A. 알림 센터 = A1 × A2 머지 [Sean 확정]
- **A2에서**: 다크 포레스트 톱 위젯 + 라이브 티커 1줄 (최신 미읽음 실데이터) + 수직 타임라인 레일 (일정 탭 상태 컬러 스키마 공유).
- **A1에서**: 날짜 그룹 마커 = 회전 원형 소인 스탬프 (레일 위에 걸림) + 알림 아이템 포맷 (아이콘 칩 + 제목/본문 + NEW 볼트 씰).
- 합성: 다크 헤더(티커) → 레일 타임라인 → 소인 스탬프가 날짜 구간을 끊고 → A1 포맷 카드가 레일에 매달림. 히어로 모티프 = 레일(트레이스), 소인은 보조 — 화면당 1히어로 규칙 유지.

### 1-B. 러너 캘린더 = C1 × C2 머지 [Sean 확정]
- **C1에서**: 톱 위젯 = 다크 출발 보드 (스플릿-플랩 예상 수익 카운터 + 확정 건수) + 상태 오벌(확정 그린/대기 앰버/완료 블루 — 기존 상태 컬러).
- **C2에서**: 작업 행 = 절취선 티켓 (우측 스터브에 실수령/예상 금액, 노치+대시), 완료 티켓엔 FINISHER 도장 오버레이.
- 수익 숫자는 전부 실데이터 (fetchRunnerJobs 실 net — 이미 연결됨).

### 1-C. 커뮤니티 = 인스타 스타일 풀와이드 피드 [Sean 방향 확정]
- 풀와이드 스크롤 (엣지-투-엣지 사진, 카드 수프 은퇴), 인스타/스트라바식 인터랙션:
  더블탭 발자국(🐾 좋아요), 댓글, 공유(→인증샷 스튜디오 연결), 팔로우는 v2 검토.
- 포스트에 러닝 데이터 오버레이 (km·페이스·코스 패치 칩) — 스트라바 액티비티 카드 문법.
- 상단에 내 클럽 진입 스트립 (하이클럽 P1과 연결).

## 2. 하이클럽 — 동네 그룹런 시스템 [Sean 아이디어, 빅 피처]

### 2-1. 컨셉 (Sean 원문 정리)
- 동네 기반 하이클럽: 로컬 이벤트(그룹런)가 자동으로 뜨고, 사람들이 가입·참여.
- 러너가 그룹런용 가용시간을 열면 → 보호자들이 강아지를 그룹런에 신청 (위탁 그룹런).
- 유저가 직접 그룹/클럽을 만들 수 있고, 동네 주민들이 가입 (자율 그룹런).
- 보호자·러너 모두 클럽에서 함께 달릴 수 있음.
- 완성되면 양쪽 홈 화면의 핵심 강조 요소.
- 클럽 페이지 = M2 스타일 (클럽 사진을 톱 위젯 배경으로 업로드 가능, 동네 합산 프로그레스).
- 세션 요약 = M3 스타일 (미팅별 참가자 러닝 요약 카드 그리드, 카드 → 계정 프로필 링크).

### 2-2. 개념 모델 (스키마 초안)
```
clubs            id, name, district, kind('official'|'user'), photo_url, description,
                 created_by, created_at
club_members     club_id, profile_id, role('host'|'member'), joined_at  — 보호자·러너 모두
club_sessions    id, club_id, host_runner_id(null 가능— 자율런), scheduled_at, route_id,
                 capacity_dogs, status('open'|'full'|'done'|'cancelled'), notes
bookings         + session_id uuid null  ← ★ 핵심 설계 결정 (아래)
session_attendees id, session_id, profile_id, dog_id(null 가능), checked_in_at — 본인 참가(무료)
```

### 2-3. 핵심 설계 제안 ★ — "그룹런의 돈 단위는 기존 부킹"
위탁 그룹런의 강아지 1마리 = **기존 booking 1건 그대로** (bookings.session_id만 추가).
- 결제·슬롯 홀드·인계 확인·보험 기점·GPS·정산(settle_run_tx)·마일·패치 — **전부 무수정 재사용**.
  이번에 하네스로 검증한 정산 파이프라인이 그룹런에도 그대로 방어선.
- 러너 수익 = 참가 부킹 N건의 정산 합 — 그룹런이 러너의 수익 레버 (시간당 N배).
  '샵의 첫 고객은 러너' 전략과 동형: 그룹런은 공급측 동기 구조.
- 정원 선점 = 기존 원자 선점 패턴 (session capacity 조건부 UPDATE — runner_id IS NULL 선점과 동일 문법).
- 본인 참가(자기 개 데리고 직접 뜀)는 돈 없음 → bookings와 분리된 session_attendees.
  v1은 체크인만 기록 — 본인 GPS 기록은 새 기능이라 v2 (측정 사칭 금지: 기록 없는 참가는 기록 없음으로 표시).

### 2-4. 안전 가드레일 (신뢰가 제품의 축)
- 러너 1인 동시 핸들링 상한: capacity_dogs = min(티어 상한, 호스트 설정). 티어 상한 제안: certified 2 · veteran 3 · master 4.
- 인계는 부킹별 개별 미트업 플로우 유지 (시간·장소만 공유) — 장비 체크리스트·양측 확인 그대로.
- 개 궁합(체중/에너지) 사전 필터는 fit 실화(매칭 v2)와 함께 — v1은 호스트 러너 수동 승인으로 대체.
- 보험: 부킹 단위 유지라 그룹이어도 로직 무변.

### 2-5. 자동 로컬 이벤트 — 정직 원칙 적용
"이벤트가 자동으로 뜬다"의 v1 해석: **유령 이벤트 금지** — 실제 호스트가 연 세션만 노출.
- P1: 동네 공식 클럽 자동 생성 (district별 1개, 첫 활동 시) — 클럽은 자동, 세션은 사람이.
- P2: 러너가 가용시간에 '그룹런 슬롯' 마크 → 세션으로 자동 게시 (러너 = 실호스트).
- P4: 수요 기반 자동 제안 ("이 시간대 신청 대기 3마리 — 세션 여시겠어요?") — 러너에게 제안만, 개설은 사람.

### 2-6. 인센티브 연결 (기존 경제와 정합)
- 위탁 부킹: 기존 완주 보상 그대로 (마일 +50, 패치, 드랍) — 신규 로직 0.
- 클럽 리더보드: 주간 클럽 합산 km (M2 프로그레스 — RPC 1개), 클럽 간 동네 대항전은 v2.
- 클럽 패치: 세션 완주 수집 (패치 사다리 문법 재사용). 본인 참가 보상은 기록 실화 전 금지.

### 2-7. 홈 화면 노출 (완성 시 — Sean: 양쪽 홈 핵심 강조)
- 보호자 홈: '이번 주 동네 그룹런' 카드 — 다음 세션 1개 + 참가 아바타 스택 + 남은 자리. 실세션 있을 때만 그림.
- 러너 홈: '그룹런 호스트하기' CTA + 내 호스팅 세션 현황 (신청 N/정원).
- 기존 홈 다크 앵커와 충돌 금지 — 클럽 카드는 라이트 + 볼트 액센트.

### 2-8. 페이즈 분할 (go-backable 단위)
- **P0** 확정 UI 머지 3종 (1-A·1-B·1-C) — 로직 무변, 즉시.
- **P1** 클럽 코어: clubs/club_members + 공식 동네 클럽 자동 생성 + 클럽 페이지(M2, 사진 배경 업로드) + 주간 합산 RPC + 커뮤니티 클럽 스트립.
- **P2** 위탁 그룹런: club_sessions + bookings.session_id + 정원 원자 선점 + 러너 호스트 플로우(가용시간 연동) + 보호자 신청 플로우 + 세션 요약(M3).
- **P3** 자율 참여: session_attendees(체크인) + 유저 생성 클럽 + 정기 세션 반복(0026 크론 패턴 재사용).
- **P4** 고도화: 본인 러닝 GPS 기록 · 그룹 할인 · 수요 기반 세션 제안 · 클럽 대항전.

### 2-9. 결정 필요 (Sean)
1. 그룹런 가격: v1 일반가 유지(추천 — 할인 약속은 실화 후) vs 그룹 할인 즉시 도입.
2. 러너 핸들링 상한: 티어 연동 2/3/4(추천) vs 고정 vs 러너 자율.
3. 순서: P0 → P1 → P2 순차(추천) vs 클럽(P1) 먼저 보고 UI 머지는 뒤로.
4. 자율 참여(P3)를 P2에 당길지 — 두 끝 시스템을 한 번에 여는 부담 vs 클럽 활성 속도.
