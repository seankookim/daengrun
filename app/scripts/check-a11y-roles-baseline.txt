# check-a11y-roles.mjs baseline — `<Pressable>` elements under app/ + src/ that carry no
# `accessibilityRole`. Opened 2026-09-23 with 163 across 33 files, immediately after the HIG
# a11y sweep gave roles to 28 taps on seven screens (alerts · owner/home · runner/home ·
# runner/return-seal · cards · runner/requests · owner/live).
#
# ── FORMAT v2 (2026-09-25) — ONE LINE IS ONE ELEMENT ──────────────────────────────────────────
#   <path> :: <nearest named ancestor> :: <8-hex shape hash> :: <n>
#
# v1 keyed this ledger on PER-FILE COUNTS, and that was a hole a cold reviewer measured rather
# than a hole anyone reasoned about. Codex, 2026-09-25 (`docs/reviews/2026-09-25-client-since-
# da47510-codex-verdict.md` #4): removing the role from `owner/schedule.tsx`'s 다시 시도 button
# made v1 exit 1 — and ALSO adding a role to a different bare Pressable in the same file made
# THAT SAME REGRESSION EXIT 0, because the count nets to zero. Re-measured in a lab copy before
# the rewrite: v1 printed 「162건 기준선 그대로」 and exited 0 on a tree where an accessible
# control had just stopped announcing itself. v1's header NAMED this blind spot and declined to
# close it; naming it did not stop it being the thing that bit.
#
# A fingerprint identifies an element by WHAT IT IS — its enclosing named function/const, its tag,
# its attribute names and normalised attribute values, and the first visible text inside it — and
# never by its line, so it survives the unrelated edits that churn these screens daily. Both
# halves of the rule are load-bearing: a bare element with no ledger line FAILS (new debt, even if
# something else in the same file was fixed in the same commit), and a ledger line with no element
# FAILS (stale — delete it). So the ledger can only shrink.
#
# ⚠ THE TRADE-OFF, PAID DELIBERATELY: a fingerprint MOVES when the component it sits in is
#   renamed, when a role-less element's own copy or props are edited, or when it moves to another
#   named ancestor. That reddens the gate as one stale line + one new line. The repair is
#   `node scripts/check-a11y-roles.mjs --rewrite-baseline` IN THE SAME COMMIT, and the rewrite
#   REFUSES to grow this file (it exits 1 and prints every addition), so re-emitting cannot be
#   used to absorb new debt. Including the element's visible text is what makes a row of otherwise
#   identical chips distinguishable — exactly where the fix-one/add-one hole would reopen — which
#   is why the copy sensitivity is paid rather than avoided.
#
# ⚠ NAMED GAP, not closed and deliberately not pinned (a limitation is prose): two bare tappables
#   with the same tag, the same attribute shape, the same first text, inside the same named
#   ancestor form ONE bucket separated only by the trailing ordinal — so fixing one of them while
#   adding another identical bare one still nets to zero. Measured at the v2 rewrite (the figure
#   `--rewrite-baseline` prints): 9 such buckets covering 21 of the 162 elements, so the hole is
#   exactly 21 elements wide. Strictly narrower than v1's, which was all 162; not zero.
#
# ⚠ The migration from v1 was mechanical and is CHECKABLE: the emitted ledger's per-file counts
#   are IDENTICAL to v1's 33 lines, file for file (162 → 162, `diff` clean). Nothing was absorbed
#   and nothing was dropped in the format change.
#
# ── THE CONTROL TEST, re-run at the v2 rewrite (2026-09-25) ───────────────────────────────────
# The standing rule is that a new detector's first obligation is to disagree with the crudest
# version of itself and to explain every difference in BOTH directions.
#
#   population   `grep -ro '<Pressable' app src --include=*.tsx`  →  643 occurrences
#                Babel-parsed JSX elements                        →  643 elements
#                exact agreement, so the gate is looking at the same population the eye sees.
#                Also measured, and each is why a whole class of miss is absent rather than
#                merely unobserved: `<Pressable` inside a comment → 0 · `<Pressable` in a `.ts`
#                file (the walk only reads `.tsx`) → 0 · the legal-but-unused spaced form
#                `< Pressable` → 0 · `<Touchable*` anywhere → 0 · elements carrying a
#                `{...spread}` (which this gate exempts, since the role could be inside it) → 0.
#
#   answer       crude `grep -n '<Pressable' | grep -v accessibilityRole`   →  441
#                this gate                                                  →  162
#
#   the 279 the crude version ADDS are every one of them a multi-line element whose
#   `accessibilityRole` sits on a LATER line: 643 elements, 481 with a role, of which 202 write it
#   on the opening line and 279 on a line of their own (162 + 279 = 441, the crude number exactly).
#   This codebase formats nearly every Pressable with more than two props across lines, so the
#   crude version is wrong about 63% of its own hits. The crude version DROPS nothing at all:
#   0 of the gate's 162 are invisible to it, because a role-less element has no
#   `accessibilityRole` anywhere to accidentally match. That asymmetry is the whole reason this is
#   parsed rather than grepped — a gate that cried 279 times on correctly-labelled buttons would
#   be `--no-verify`'d within a day and then protect nothing while everyone believes it is on.
#
# ── WHAT A LINE HERE IS AND IS NOT ────────────────────────────────────────────────────────────
# It is debt, not amnesty, and it is NOT a claim that these 162 all need a role. Some genuinely
# should not have one — a decorative press-scale wrapper, a gesture catcher. Those want the
# escape hatch (`// a11y-role-ok: <reason>` on the element's opening line, reason required), which
# removes them from the count permanently and says why. Nobody has triaged these 162 yet; a line
# here means only "this element had no role on the day it was written down."
